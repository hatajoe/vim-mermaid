1. Introduction				*mermaid* *vim-mermaid* *mermaid-introduction*

vim-mermaid renders a ```mermaid fenced code block of a Markdown buffer as
ASCII art and shows it in a popup window below the cursor, or in a scratch
split (see |g:mermaid_display|). It runs the external command mermaid-ascii
(https://github.com/AlexanderGrooff/mermaid-ascii).

==============================================================================
2. Requirements						*mermaid-requirements*

- Vim 9.1 or later with |+job| and |+timers|. Neovim is not supported.
- Popup mode (the default) also needs |+popupwin|. Split mode does not.
- mermaid-ascii. Install it with: >
	go install github.com/AlexanderGrooff/mermaid-ascii@latest
<
Diagram types that mermaid-ascii rendered in our checks:
- graph / flowchart (direction TD, TB, BT, LR, RL)
- sequenceDiagram
- erDiagram
Other types (classDiagram, stateDiagram-v2, pie, ...) fail; the error text of
mermaid-ascii is shown in the popup or the split.

==============================================================================
3. Commands						*mermaid-commands*

							*:MermaidPreview*
:MermaidPreview		Render the mermaid block under the cursor. The cursor
			may be on the opening fence, the body, or the closing
			fence. The cursor stays in the source window.

							*:MermaidPreviewAll*
:MermaidPreviewAll	Render every mermaid block of the buffer into one
			popup or the split. Each block starts with a header line
			"-- line N --", where N is the opening fence line.

							*:MermaidClose*
:MermaidClose		Close the preview popup and the preview split of the
			current tab page, and stop a running render.

==============================================================================
4. Mappings						*mermaid-mappings*

					*<Plug>(mermaid-preview)*
<Plug>(mermaid-preview)	Same as |:MermaidPreview|.

There are no default mappings. Example: >
	autocmd FileType markdown nmap <buffer> <Leader>mp <Plug>(mermaid-preview)
<
==============================================================================
5. Options						*mermaid-options*

						*g:mermaid_ascii_cmd*
g:mermaid_ascii_cmd	Path of the renderer. The path may contain spaces.
			Default: 'mermaid-ascii'

						*g:mermaid_ascii_args*
g:mermaid_ascii_args	List of extra arguments for the renderer. The plugin
			always appends "-f -" and sends the block on stdin.
			Example: ['-a'] draws with ASCII characters only.
			Default: []

						*g:mermaid_display*
g:mermaid_display	Where the diagram is shown: 'popup' or 'split'. Any
			other value gives an error and nothing is rendered.
			Default: 'popup'

					*g:mermaid_popup_maxheight*
g:mermaid_popup_maxheight
			Maximum height of the popup text. A longer diagram
			gets a scrollbar.
			Default: &lines - 4 (at least 1)

					*g:mermaid_popup_maxwidth*
g:mermaid_popup_maxwidth
			Maximum width of the popup text.
			Default: &columns - 4 (at least 1)

						*g:mermaid_split*
g:mermaid_split		'vertical' or 'horizontal'. Split mode only.
			Default: 'vertical'

						*g:mermaid_auto_refresh*
g:mermaid_auto_refresh	Split mode only. When 1, saving the source buffer of
			an open preview split renders it again (see
			|mermaid-behavior|). In popup mode saving does
			nothing.
			Default: 0

						*g:mermaid_timeout_ms*
g:mermaid_timeout_ms	Stop the renderer after this many milliseconds and
			show "timed out" in the popup or the split.
			Default: 5000

==============================================================================
6. Behavior						*mermaid-behavior*

Fenced blocks follow CommonMark: an opening fence is 3 or more backticks or
tildes with 0-3 spaces of indent. The closing fence uses the same character,
is at least as long, has 0-3 spaces of indent and no info string. A block
is a diagram only when the first word of its info string is "mermaid". A
mermaid fence inside another fenced block is plain text. An unclosed mermaid
block runs to the end of the buffer.

Popup mode ~
The popup opens below the cursor when the render is done. Vim moves it when
it does not fit on the screen. Each tab page has at most one preview popup;
a new preview closes the old one. The popup closes when:
- the cursor moves,
- <Esc> is pressed in Normal mode (other keys work as usual), or
- |:MermaidClose| is run.
The render result is dropped and no popup opens when, before the render is
done, the cursor moves, the text changes, or you leave the window or the
buffer. Popup mode needs |+popupwin|. Without it the commands give an error;
set |g:mermaid_display| to 'split' instead.

Scrolling the popup ~
							*mermaid-popup-scroll*
A diagram taller than |g:mermaid_popup_maxheight| gets a scrollbar. While the
popup is open, these keys in Normal mode scroll it:

	CTRL-J		one line down
	CTRL-K		one line up
	CTRL-D		half a page down
	CTRL-U		half a page up

The popup stays open. At the top or the bottom the keys do nothing. When the
whole diagram fits, the keys also do nothing, but they still do not reach
Vim. When no popup is open, the keys work as usual.

The mouse wheel also scrolls the popup. This needs 'mouse' set, for example
`:set mouse=a`, and a terminal that sends mouse events to Vim.

Split mode ~
Each tab page has at most one preview split. The commands reuse it. The
preview buffer has 'buftype' "nofile" and 'filetype' "mermaid-ascii".

A new preview or |:MermaidClose| stops a running render, and the output of
the stopped render is dropped.

When |g:mermaid_display| is 'split', |g:mermaid_auto_refresh| is 1, and the
source buffer is saved:
- after |:MermaidPreviewAll|, all blocks are rendered again.
- after |:MermaidPreview|, the plugin finds the block at the stored opening
  line, or the first mermaid block after it. If there is none, the split
  shows "mermaid: block not found".
Saving other buffers does not change the preview. After the split is closed
(also with |:quit|), saving never opens it again.
